Below is a *minimal, bounded skill set* that will let you create _clear,
publication-ready mini family trees_ without learning the rest of the
system.

'''''

== The only Graphviz you need to know (for mini family trees)

You will reuse *one template*, changing only names and dates.

'''''

=== 1. One fixed template (copy once, reuse forever)

Create a file called, for example:

....
mini-tree.dot
....

[source,dot]
----
digraph Family {
  rankdir=TB;
  node [shape=box fontsize=10];
  edge [fontsize=9];

  Father [label="Johann Heinrich Krückeberg\n* 1768\n† 1832"];
  Mother [label="Anna Maria Elisabeth Möller\n* 1771\n† 1814"];
  Child1 [label="Anna Maria Philippina Blecke\n* 1773"];

  Father -> Child1 [label="father"];
  Mother -> Child1 [label="mother"];
  Father -> Mother [dir=none label="m. 1792"];
}
----

That is *95% of what you will ever need*.

'''''

=== 2. The only command you need

[source,bash]
----
dot -Tsvg mini-tree.dot -o mini-tree.svg
----

That’s it.

You now have an image you can:

* embed in Antora / AsciiDoc
* include in PDFs
* reuse in print

'''''

=== 3. The only edits you will ever make

You will *only* change:

==== A) The labels (names & dates)

[source,dot]
----
[label="Name\n* birth\n† death"]
----

==== B) Add or remove children

[source,dot]
----
Child2 [label="Johann Heinrich\n* 1801"];
Father -> Child2;
Mother -> Child2;
----

==== C) Remove the marriage line if irrelevant

[source,dot]
----
Father -> Mother [dir=none label="m. 1792"];
----

That’s all.

'''''

=== 4. What you can safely ignore forever

You do *not* need to learn:

* layout engines (`+neato+`, `+fdp+`, etc.)
* clusters
* subgraphs
* HTML labels
* styling beyond `+shape=box+`
* advanced attributes

If you stick to:

[source,dot]
----
digraph + node labels + arrows
----

Graphviz will do the rest correctly.

'''''

=== 5. Genealogically correct reading (important)

This convention is *standard and intuitive*:

* *Parents → children* = biological relationship
* *Undirected line between spouses* = marriage
* No implied ancestry beyond what is drawn

This matches how readers interpret pedigree fragments in scholarly
genealogies.

'''''

=== 6. How this fits proof writing (best practice)

For each proof argument:

* One paragraph = one diagram
* Show _only_ the relationships you are proving
* Do *not* show the entire tree

This mirrors how genealogical journals (e.g., NGSQ) use figures.

'''''
