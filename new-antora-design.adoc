= New Design

You **do not** need four repositories unless you *want* that complexity.

Given what you described, here is the cleanest structure that will:

✅ keep your **event-table work** separate
✅ keep your **research-plans module** intact for the historian
✅ allow **background/reference modules** to exist without forcing a narrative link
✅ avoid Antora navigation chaos
✅ avoid breaking all your existing cross-refs
✅ avoid the “Immanuel disappears from nav” nightmare you already experienced

# ✅ Recommended structure (simplest and scalable)

## **1. ONE Git repository for *all content modules***

This repo contains:

```
modules/
  ROOT/                   (general landing pages if needed)
  research/               (your research plans & rationale for the historian)
  event-tables/           (the tables you are developing)
  schaumburg-background/  (historical context, geography, customs)
  land-records/           (Kammerkauf, Ausweisung, Rottländer, etc.)
  swaplands/              (U.S. 1850 context)
  other-background/       (anything else)
antora.yml                (component descriptor)
```

This repository is **a single Antora component** with multiple modules.

### Why this is ideal

✅ Navigation stays clean
✅ Researcher sees only what you expose in nav.adoc
✅ Modules stay logically separated
✅ No duplication of assets folder, UI, etc.
✅ You avoid multi-repo synchronization headaches

---

## **2. ONE separate repository ONLY IF it’s a distinct component**

Examples that *do* merit a separate repo/component:

✅ **Immanuel Lutheran** churchbooks
✅ **Petzen / Frille / parish-specific** record sets
✅ **Your eventual ACTA case file edition**

Reason: those are **publishable bodies of evidence**, not background.

---

## **3. ONE “umbrella” playbook repo IF—you want automated website builds**

Only create this if:

* your genealogical research repos live separately, **AND**
* you want a VPS or GitHub Action to build everything together

This playbook repo contains:

```
antora-playbook.yml
ui/ (optional)
scripts/
README.md
```

### When to skip it

If you are building **locally only**, don’t create a playbook repo.

# ✅ Suggested nav strategy

Each module in the **research-context** component gets its own nav file:

```
modules/research/nav.adoc
modules/event-tables/nav.adoc
modules/schaumburg-background/nav.adoc
modules/land-records/nav.adoc
modules/swaplands/nav.adoc
```

In `antora.yml` for that component:

```yaml
nav:
  - modules/research/nav.adoc
  - modules/event-tables/nav.adoc
  - modules/schaumburg-background/nav.adoc
  - modules/land-records/nav.adoc
  - modules/swaplands/nav.adoc
```

### Result:

✅ historian sees a clean Research section
✅ you see Event Tables clearly
✅ background/reference stays accessible but separate
